## What this is
A mobile real-time strategy game (formerly Colony Mobile) in a single self-contained HTML file (index.html). It plays in landscape on iPhone with no dependencies and no network once loaded. Since v2.57 the source is in src/ and `npm run build` (build.js, no dependencies) joins it into index.html: edit src/, never index.html directly, then build and commit both (tests/build.test.js checks they match). The code is organized into marked sections: SIM (rules, combat, AI), RENDER (drawing) and UI (HUD, input, menus).

## Features that must keep working (regression checklist)
- Select and command (v2.74, refined v2.76–v2.80, docs/CONTROLS.md): tap, double-tap a type (on screen), the rectangle box, All, tap a lane; tap the ground to move; tap an enemy to target it (v2.80: then fall back out of enemy defences' reach); Attack (a lane picker on lane maps), Hold and Retreat on the selection; the base rally point and spacing; control groups (hold, tap, double-tap); 1–3× speed; pause; Easy, Normal and Hard difficulty.
- Overview minimap inside the top bar (tap or drag to jump).
- Top bar sits BELOW the viewer's top strip. The Claude artifact viewer swallows taps in that strip, so nothing interactive may go there. Sky and scenery may fill it.
- Build by tapping an empty pad then a card, or just a card. Tap the same spot again to cycle through overlapping buildings.
- Building upgrades T1–T3, two-tap Sell (50% refund), paid Repair plus slow self-repair, Turret building.
- Field nodes (capture for income) and the HQ shield (HQ is invulnerable while any other building stands).
- Long-press a card for unit or building info.
- Auto-save and resume via localStorage keys `colonyMobile.save` and `colonyMobile.diff`. Never rename these keys.

## Testing
- Run `npm test` before every push. It must pass.
- `npm test` is the fast suite (tests/*.test.js). The long statistical tests live in tests/slow/ and run with `npm run test:slow` (about 21 minutes on 4 cores). Run `npm run test:slow` too, with 0 failures, before any commit that touches the SIM (src/sim/) or the AI, and say in the report that you ran it. A new test that plays many full matches belongs in tests/slow/.
- Run npm test as its own command, read the result, and push only if it reports 0 failures. Never chain a push onto the test command.
- When a task is finished and npm test passes with 0 failures, merge the work into main and push main, so GitHub Pages serves the new version. Report the commit on main and the version number.
- Before merging (and at the start of a session), run `git fetch origin main` and fast-forward to `origin/main`: work from origin/main, never from the local `main` ref, which in this workspace can be stale (it once held v2.72-era history). Merge onto a fresh origin/main and push that.
- The test kit lives in tests/ and loads the SIM section headlessly in Node.
- Every balance claim must come from test scripts, reported as win counts over at least 20 matches.
